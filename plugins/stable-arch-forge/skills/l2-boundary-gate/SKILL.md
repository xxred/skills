# 边界门禁与白名单约束落地技能

## 1. 架构来源引用

> 引自 `../docs/02_agent_dev_architecture.md`

边界门禁用于拦截越界行为；白名单明确允许范围，**不在白名单内默认禁止**。

- **技术栈白名单**：预先定义允许使用的语言、框架、库。不在白名单默认拒绝。
- **职责门禁**：Agent 只能修改自己职责范围内的产物；修改其他模块产物必须走审批流转。
- **架构门禁**：新增模块/接口必须对齐架构模型，巡检 Agent 检测架构不一致，标记偏差。

## 2. 输入条件

- L2-01 `l2-global-spec` 输出的 `project_global_spec.md`

## 3. 分步执行动作

1. 从架构基线提取门禁规则、白名单、黑名单、触发条件。
2. 整理技术栈白名单清单，明确默认拒绝原则。
3. 整理职责门禁：各 Agent/模块允许修改的产物范围。
4. 整理架构门禁触发条件：新增模块、接口、依赖触发校验。

## 4. 输出物清单

- `boundary_gate_spec.md`：边界门禁与白名单规范文档（技术栈白名单 / 职责门禁 / 架构门禁）。

## 5. 门禁校验（强制）

> 全部满足才算通过；不通过不得进入 L3-01。

- [ ] 遵守"不在白名单默认禁止"原则
- [ ] 全部门禁条件均来自原始架构文档，无自定义新增规则

## 6. 更新说明

架构白名单/门禁规则变更时同步更新本技能输出。

## 完成态与下一步

- **完成态检查**：本技能正文定义的全部步骤与交付物已产出；按技能正文门禁项逐项校验，全部通过方可视为完成。
- **硬约束**：门禁未全部通过前，禁止进入下一技能；偏差按 L0~L4 分级处置，L3 以上必须暂停并上报，不得继续。
- **下一步**：执行「l3-target-field-design」技能（dependsOn 链顺序）。
- **发现架构矛盾时**：禁止修改本技能绕过约束，必须先更新 `docs/` 基线并记录 `arch-version-log.md`，再同步本技能与 MCP 工具规则。
