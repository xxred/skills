# 架构一致性守护技能

## 1. 架构来源引用

> 引自 `../docs/03_full_detail_design.md`

架构守护机制：每次重大迭代结束，执行架构一致性审计——对比当前系统模型和原始架构基线，记录漂移；漂移超出阈值，触发架构重构，防止长期累积形成癌变。

## 2. 输入条件

- 全套分层设计文档
- 迭代日志、处置记录（L4-01/L4-02 输出）

## 3. 分步执行动作

1. 读取架构基线文档，提取基准架构模型。
2. 将当前项目系统模型和基线模型逐项比对。
3. 计算架构漂移程度，记录漂移点。
4. 判断漂移是否超出阈值：
   - 未超限：记录，继续迭代，持续观测。
   - 超限：启动架构重构计划，修复漂移。
5. 输出审计报告，归档。

## 4. 输出物清单

- `arch_consistency_audit.md`：架构一致性审计报告（比对项 / 漂移点 / 阈值判定 / 处置结论）。

## 5. 门禁校验（强制）

> 全部满足才算通过；这是本技能链最后一道门禁。

- [ ] 审计对比使用插件内 `docs/` 原始架构基线，不使用临时修改版本
- [ ] 漂移超出阈值必须启动重构方案

## 6. 更新说明

架构审计规则变更时同步更新本技能。

## 完成态与下一步

- **完成态检查**：本技能正文定义的全部步骤与交付物已产出；按技能正文门禁项逐项校验，全部通过方可视为完成。
