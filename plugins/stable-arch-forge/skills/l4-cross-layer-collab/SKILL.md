# 跨层协同流程落地技能

## 1. 架构来源引用

> 引自 `../docs/03_full_detail_design.md`

四层架构跨层交互必须受控：

- 下层不能反向修改上层定义（如边界约束层规则不可被业务 Agent 修改）。
- 跨层变更必须触发架构评审与稳态巡检，评估对目标场、边界约束的影响。
- 冲突处理：Agent 之间出现冲突时提交巡检 Agent + 架构 Agent 评审，不能自行突破边界解决冲突。

## 2. 输入条件

- 全部 L3 分层设计文档
- 偏差处置记录（L4-02 输出）

## 3. 分步执行动作

1. 识别需要跨层的变更请求。
2. 评估变更是否会影响上层目标场或底层边界约束。
3. 启动跨层评审：架构 Agent + 巡检 Agent 共同评审。
4. 评审通过，执行变更并触发全量巡检；评审驳回，终止变更。
5. 记录跨层变更，更新目标场状态。

## 4. 输出物清单

- `cross_layer_collab_record.md`：跨层协同与变更评审记录（变更内容 / 影响评估 / 评审结论 / 巡检结果）。

## 5. 门禁校验（强制）

> 全部满足才算通过；不通过不得进入 L4-04。

- [ ] 不允许下层直接修改上层定义
- [ ] 所有跨层变更均经过架构评审 + 稳态巡检

## 6. 更新说明

跨层协同规则变更时同步更新本技能。
