# AI编程多Agent系统「发育稳态」详细设计

- 所属插件：stable-arch-forge
- 文档版本：v1.0.0
- 上游基线：`01_meta_architecture.md` v1.0.0、`02_agent_dev_architecture.md` v1.0.0
- 配套技能：本插件 `skills/` 目录下 L1~L4 全套技能
- 推进原则：按「全局规约→模块分化→协同组网→稳态闭环」分阶段发育，全程嵌入对齐校验门禁

---

## 0. 设计总纲

### 0.1 输入（唯一基线，禁止偏离）
《顶层元架构》《AI编程落地架构》两份基线文件。

### 0.2 总输出物体系（5类标准化交付物）
1. **全局规约类**：所有模块必须遵守的统一标准与边界规则
2. **模块设计类**：四层架构中每个独立模块的详细设计
3. **交互接口类**：模块间、Agent间的通信协议与接口定义
4. **稳态规则类**：巡检、校验、偏差响应的详细规则与阈值
5. **落地指引类**：实现顺序、部署方案、验证方案

### 0.3 全程一致性保障机制（四机制）
1. **单源基线原则**：设计输入唯一来源是上一阶段校验通过输出；变更走统一流程（申请→影响评估→全链路同步）
2. **阶段门禁校验**：每阶段结束必须通过门禁，校验者与设计者隔离
3. **邻域交叉评审**：模块设计完成后由其上下游关联模块设计人员交叉评审
4. **偏差追溯机制**：所有设计偏离点记录在案（原因、影响、回退方案）；架构级偏离立即触发全局修正

## 1. 阶段一：全局设计规约与边界定义

> 生物对应：胚胎体轴建立与外边界形成。本阶段输出为所有后续设计的唯一刚性基线。

### 1.1 技术与动作空间规约

**技术栈白名单**（管控：私有镜像源 + Git Pre-commit钩子 + CI流水线三级硬拦截）：

| 分类 | 允许范围 | 版本约束 | 禁止项 |
|------|----------|----------|--------|
| 前端语言 | TypeScript | 5.4+，严格模式 | 原生JavaScript、Any类型滥用 |
| 前端框架 | Vue 3.x | 3.4+，Composition API | Options API、全局状态直接修改 |
| 后端语言 | C# / Python | C# 10.0+ / Python 3.10+ | 动态类型滥用、反射绕过类型检查 |
| 后端框架 | .NET 8 / FastAPI | 固定大版本 | 非官方维护的第三方框架 |
| 数据库 | MySQL 8.0 / Redis 7.x | 固定小版本 | 非标SQL语法、客户端直连主库 |
| 依赖包 | 官方源认证包 | 锁定版本号，禁止自动升级 | 未审计第三方包、修改源码的本地包 |

**Agent工具权限矩阵**（平台层角色权限隔离，越权调用直接拒绝）：

| Agent角色 | 代码库权限 | 工具调用权限 | 系统操作权限 | 禁止权限 |
|----------|------------|--------------|--------------|----------|
| 需求分析Agent | 只读（文档目录） | 需求拆解、原型解析工具 | 无 | 修改代码、调用部署接口 |
| 架构设计Agent | 只读（全量） | 架构分析、依赖分析工具 | 无 | 提交代码、合并分支 |
| 前端/后端开发Agent | 读+开发分支写 | 代码生成、静态检查工具 | 本地单元测试执行 | 合并主分支、修改生产配置、越权修改其他模块代码 |
| 测试用例Agent | 读+测试分支写 | 用例生成、测试执行工具 | 测试环境执行 | 修改业务代码、访问生产数据 |
| 各类巡检Agent | 只读（全量） | 扫描、分析工具 | 无 | 修改任何代码、配置 |
| 平台管控引擎 | 全量读写（仅规则配置） | 权限管理、门禁控制 | 流程拦截 | 执行业务逻辑、生成业务代码 |

**代码输出格式标准**（提交前自动格式化校验）：
- 目录结构：严格分层（`api/`、`service/`、`dao/`、`entity/`），禁止跨目录乱放
- 命名规范：帕斯卡类名、驼峰方法名、下划线数据库字段，禁止拼音/缩写命名
- 注释规范：接口、类、核心方法必须含功能与入参出参说明
- 接口输出：统一响应结构体 `{code, message, data, timestamp}`

### 1.2 数据与接口统一标准

**全局目标场向量格式标准**（全局唯一，禁止自定义口径）：

| 维度 | 量化方式 | 取值范围 | 计算口径 |
|------|----------|----------|----------|
| 需求对齐度 | 需求向量Embedding余弦相似度 | 0~1 | 以原始PRD为基准向量 |
| 架构合规度 | 依赖关系匹配度+分层规则符合率 | 0~1 | AST扫描违规占比，分层60%+依赖40% |
| 代码质量分 | 静态扫描得分加权 | 0~100 | SonarQube：bug率30%+异味30%+复杂度20%+重复率20% |
| 交付进度值 | 里程碑完成率 | 0~1 | 完成节点数/总节点数 |

**Agent间消息协议标准**（统一消息总线）：
```json
{
  "msg_id": "全局唯一消息ID", "version": "协议版本号",
  "sender": "发送方AgentID", "receivers": ["接收方AgentID列表"],
  "msg_type": "request/response/event/broadcast",
  "timestamp": "毫秒级时间戳", "trace_id": "全链路追踪ID",
  "payload": "业务载荷", "signature": "消息签名"
}
```
- 版本规则：语义化版本，升级必须兼容至少一个历史版本
- 错误码：全局统一错误码表

**接口契约统一规范**：RESTful风格、URL名词复数、小驼峰字段命名、入参前置校验、URL携带版本号（`/api/v1/xxx`）

### 1.3 设计元规则
- 模块划分：严格四层，模块只能同层或向下调用，禁止向上/跨层调用；禁止循环依赖；单模块职责单一
- 设计文档模板：强制包含架构追溯字段（对应顶层架构组件ID与规则条目）
- 版本管理：语义化版本（架构变更升主版本）；变更留痕（原因/内容/影响/评审人）；更新后自动广播关联模块

## 2. 阶段二：核心分层模块详细设计

> 生物对应：器官分化。按「目标场层 → 自组织协同层 → 稳态控制层 → 边界约束层」逐层细化，每模块必须含架构追溯字段、目标对齐方式、偏差自检逻辑。

### 2.1 第1批：全局目标场层模块

**模块1 需求-架构双编码器**
- 职责：将PRD/原型/架构方案转化为可计算目标向量，目标场输入入口
- 子模块：需求结构化编码（文档分段→Embedding→需求树）、架构约束编码（规则解析→规则库→约束向量）、目标场合成（四维权重默认 需求40%+架构30%+质量20%+进度10%）
- 偏差自检：需求点覆盖率100%、规则完整性、场连续性

**模块2 实时梯度计算器**
- 职责：任意Agent实时计算目标梯度与偏差值，Agent获取行动方向唯一入口
- 子模块：上下文接入、偏差计算（四维余弦相似度/规则匹配/静态扫描/里程碑）、优化方向生成
- 标准接口：
```
getDevGradient(agentId, currentContext): {
  globalDeviation, dimensionDeviation{requirement, architecture, quality, schedule},
  optimizePriority[], suggestAction[]
}
```
- 约束：Agent完成每个原子操作自动触发一次；综合偏差>0.3预警、>0.5阻断提交

**模块3 全局状态总线与版本控制器**
- 职责：目标场版本一致性、实时广播
- 子模块：状态总线（发布-订阅、至少一次投递、全链路延迟≤100ms）、版本控制（自动版本号+快照+留痕）、冲突处理（并行变更检测、影响评估、一键回滚）

### 2.2 第2批：自组织协同层模块

**模块1 邻域拓扑管理器**
- 职责：维护邻域关系拓扑与横向通信链路
- 子模块：邻域关系定义（上/下/对等三类，至少2个对等节点，禁止孤岛）、链路健康监测（超时剔除+备用切换）、拓扑可视化

**模块2 横向共识协议模块**
- 职责：邻域输出交叉校验、状态同步
- 子模块：接口契约双向校验（字段级比对，不通过阻断提交）、模块交叉评审（至少2个邻域节点校验）、偏差同步拉平（变更事件自动推送+适配检查）
- 标准协议：`peerValidate(outputId, outputContent, neighborIds): {passed, matchScore, issues[]}`

**模块3 局部自毁触发器**
- 职责：偏离超阈值自动回滚/重试/退出
- 阈值体系：轻度 匹配度0.8~0.9 提示自动修正；中度 0.6~0.8 回滚重写；重度 <0.6 主动退出上报
- 执行：连续3次校验不通过上报稳态层；异常闭环（原因/历史/影响+恢复正常通知）

### 2.3 第3批：分层稳态控制层模块

**模块1 三级巡检器**
- 代码级实时巡检：伴随提交触发，10秒内返回结果阻断违规；扫描语法/规范/安全/复杂度/重复
- 模块级阶段巡检：里程碑全量校验（需求覆盖/架构合规/接口完整/测试通过率），未通过不得进入下一阶段
- 系统级全局巡检：每日执行，全库架构一致性、系统性偏差识别
- 标准输出：`InspectionResult{level, score, passed, issues[], systemDeviation}`

**模块2 全局反馈调控器**
- 职责：系统性偏差处理与全局纠偏（内分泌系统）
- 判定规则：3+模块同类违规 / 全局偏差持续上升超3周期 / 核心架构规则被突破
- 调整逻辑：按偏差类型调整四维权重（如架构违规时架构权重30%→40%）；梯度平滑过渡防震荡；纠偏后验证并逐步恢复默认权重

### 2.4 第4批：边界约束层模块

**模块1 动作空间门禁模块**
- 技术栈校验：私有镜像源拦截白名单外依赖；语法/版本校验（Pre-commit钩子+CI双重）
- 工具权限校验：所有工具调用经统一网关前置校验，越权拒绝+审计日志
- 输出格式校验：代码/接口/文档格式自动校验拦截

**模块2 发育路径控制模块**
- 状态机：`需求分析→架构设计→接口定义→编码实现→单元测试→代码评审→集成测试`
- 门禁：每阶段准出校验通过才流转；阶段变更须申请审批
- 追踪：全流程状态历史记录、异常流转（跳阶段/逆流程）检测阻断

**模块3 接触抑制控制模块**
- 规模阈值：单模块≤2000行（后端）/单组件≤800行（前端）、圈复杂度≤15、单文件依赖≤15
- 依赖管控：依赖深度≤3层、循环依赖实时阻断、跨层调用识别
- 上帝模块识别：职责过载/依赖过多自动触发拆分建议

## 3. 阶段三：跨层协同与流程详细设计

> 生物对应：神经血管连接。将独立模块串联为完整运行链路。

### 3.1 全链路标准运行时序（正常流）
1. **目标初始化**：需求/架构输入→双编码器生成初始目标场→版本控制器生成基准版本→全量广播→Agent订阅获取初始梯度
2. **分布式开发**：各Agent基于梯度并行工作→每原子操作调用梯度计算器→提交前动作空间门禁校验→提交后邻域交叉校验→通过则流转下游，不通过则触发局部自毁回滚
3. **分层巡检**：代码级伴随提交实时执行→模块级阶段校验→每日系统级巡检
4. **全局纠偏**：个体异常推送整改→系统性偏差调整目标场梯度→重大偏差暂停流程全量整改
5. **终态校验**：四维全面对齐校验→输出对齐度报告→达标交付/不达标返回整改

### 3.2 异常流转路径
所有异常遵循「局部处理→层级上报→全局兜底」：
- 轻度：邻域层自动修正，无需上报
- 中度：局部自毁触发，回滚重试，同步告知巡检器
- 重度：巡检器介入，限期整改，跟踪闭环
- 系统性：全局反馈调控器介入，调整目标场，全系统纠偏

### 3.3 跨层接口定义
| 接口 | 调用方 | 功能 |
|------|--------|------|
| `getDevGradient(agentId, context)` | 所有执行Agent | 梯度查询，每原子操作调用 |
| `onTargetFieldUpdate(callback)` | 所有Agent订阅 | 目标场变更通知 |
| `reportAgentStatus(agentId, status)` | 执行Agent | 状态上报，阶段完成时 |
| `reportAbnormal(agentId, info)` | 执行Agent/自毁触发器 | 异常主动上报 |
| `reportSystemDeviation(info)` | 反馈调控器 | 系统性偏差反馈 |
| `broadcastAdjustSignal(signal)` | 目标场层 | 调整信号全系统广播 |
| `checkActionPermission(agentId, action, target)` | 所有模块 | 动作前置校验，无校验不执行 |

### 3.4 邻域协同交互细则
- **前后端接口协同**：后端输出接口定义→推送前端→前端基于定义开发→自动双向校验→通过确认契约/不通过返回差异修改→接口变更必须同步通知
- **上下游交付校验**：上游输出→下游输入校验（需求理解一致+输出完整可用）→通过开工/驳回修改→驳回超3次自动上报稳态层仲裁

## 4. 阶段四：稳态校验与偏差响应详细设计

> 生物对应：免疫系统发育成熟。

### 4.1 偏离度量化细则

| 偏离等级 | 综合偏差值 | 判定场景示例 | 对应生物现象 |
|----------|------------|--------------|--------------|
| 一级（轻度） | 0.1~0.2 | 代码风格不统一、命名不规范、注释缺失 | 细胞轻微异常 |
| 二级（中度） | 0.2~0.4 | 接口字段不匹配、单模块需求偏差、轻微架构违规 | 细胞脱离邻域调控 |
| 三级（重度） | 0.4~0.6 | 多模块架构违规、核心需求遗漏、批量质量问题 | 组织级发育异常 |
| 四级（癌变级） | >0.6 | 高危安全漏洞、越权操作、严重破坏核心架构 | 恶性肿瘤 |

**计算规则**：
- 综合偏差值 = 需求偏差×0.4 + 架构偏差×0.3 + 质量偏差×0.2 + 进度偏差×0.1
- 单维度超等级阈值时按就高原则升级
- 安全类违规直接上调一级，高危漏洞直接定为四级

### 4.2 巡检规则库明细
- **代码质量巡检**（4大类32小项）：Bug类12项（空指针、资源未释放、SQL注入等）、异味10项（重复代码、魔法值、上帝类等）、复杂度6项、规范4项；来源SonarQube规则集裁剪
- **架构合规巡检**（3大类15小项）：分层5项（跨层调用、反向依赖等）、依赖6项（循环依赖、未授权依赖等）、接口4项（格式、版本、参数校验）
- **安全漏洞巡检**（2大类18小项）：依赖漏洞6项（CVE库）、代码漏洞12项（注入、敏感信息、硬编码密钥等）；来源OWASP Top10
- **需求对齐巡检**：需求点覆盖率、业务规则匹配度、非功能需求满足度

### 4.3 偏差响应执行手册

| 级别 | 触发 | 处置 | 验证 | 时效 | 上报 |
|------|------|------|------|------|------|
| 一级 | 巡检/邻域发现 | Agent自动修复或提示修正 | 修复后自动重检 | 当日 | 无需，仅记录日志 |
| 二级 | 自毁触发/巡检发现 | 回滚到上一通过版本+整改清单 | 整改后提交复检 | 2个工作日 | 告知代码级巡检Agent跟踪 |
| 三级 | 模块级巡检/连续二级未整改 | 暂停模块开发+架构师介入定位根因+全模块排查 | 整改后全量巡检 | 限期 | 同步项目负责人，记录架构偏差台账 |
| 四级 | 系统级巡检/高危漏洞/严重破坏 | 终止Agent+清除分支+回滚稳定版本+紧急排查+应急预案 | 全面复盘+评审通过恢复 | 立即 | 同步最高负责人，输出事故报告 |

### 4.4 架构一致性守护机制
- **设计变更影响评估**：所有架构变更先评估（目标场影响/其他模块影响/稳态机制影响），重大变更经架构评审
- **架构偏离检测**：每日全局巡检自动扫描，持续偏离未整改触发升级响应
- **版本同步校验**：所有模块设计版本与顶层架构版本一致；升级后模块限期适配；版本不一致禁止提交/禁止进入下一阶段
