## 0. 文档定位

本文件是顶层元架构在**企业级AI辅助编程 / 全栈多Agent协同开发**场景的完整落地设计。100%遵循元架构规则：四层结构完整、目标场唯一锚定、分布式纠偏优先、边界刚性递增、稳态优先于效率。

---

## 1. 架构定位与核心对齐

### 1.1 定位
面向全栈软件研发的多Agent协同开发体系，以全局目标场为唯一锚点，通过邻域自组织校验、分层稳态巡检、底层刚性边界三层防护，在保持AI开发效率的同时，将代码与需求/架构的偏离度控制在可接受范围内。

### 1.2 核心解决的"癌变式"痛点

| 痛点 | 表现 |
|------|------|
| 需求癌变 | 局部Agent对需求理解偏差，最终产出不符合整体业务目标 |
| 架构癌变 | 各模块独立实现，破坏整体架构一致性，依赖混乱、跨层调用 |
| 代码癌变 | 代码风格不统一、冗余逻辑、隐性bug、安全漏洞累积 |
| 协作癌变 | 模块间接口不匹配，错误到集成阶段才暴露，向下游扩散 |

## 2. 四层核心落地架构

### 2.1 全局目标场层（开发系统的「生物电位场」）

**核心职能**：将业务需求、架构规范、质量标准编码为可量化统一标量场，为所有开发Agent提供实时方向指引，是所有行为的唯一最终锚点。

**强制组件**：
1. **需求-架构双编码器**
   - 将自然语言PRD、原型图转化为结构化需求向量（功能点、业务规则、非功能要求）
   - 将技术架构方案转化为架构约束向量（分层规则、依赖规范、技术栈要求、接口标准）
   - 共同构成四维目标场：`需求对齐度、架构合规度、代码质量分、交付进度值`
2. **实时梯度计算器**
   - 为任意角色、任意模块的Agent提供目标梯度计算：输入当前代码/设计，输出「当前状态与全局目标的偏差值」和「优化方向向量」
3. **全局状态总线**
   - 低延迟广播全局目标场所有变更（需求调整、架构修改、进度更新），所有Agent权限一致，禁止信息差
4. **目标版本控制器**
   - 需求、架构所有变更版本化管理，变更留痕，版本更新强制全量广播，禁止多版本目标并存

**标准接口**：
```
getDevGradient(agentId: string, currentContext: Code/Design): {
    deviation: number,      // 全局偏差值
    direction: Vector,      // 优化方向向量
    priority: string[]      // 优先修正项
}
```

**防跑偏价值**：每个Agent的优化目标始终是全局最优，而非局部任务完成度。

### 2.2 自组织协同层（开发系统的「缝隙连接网络」）

**核心职能**：构建Agent间横向邻域拓扑，通过点对点实时校验在局部消解偏差，避免错误向下游累积。

**邻域拓扑定义**：每个Agent必须同时绑定三类邻域节点：
- **上游邻域**：任务输入方（如开发Agent的上游是需求/架构Agent）
- **下游邻域**：结果接收方（如开发Agent的下游是测试Agent）
- **对等邻域**：协作关联方（如前端Agent与后端Agent互为对等邻域）

**强制组件**：
1. **邻域拓扑管理器**：基于研发流水线自动维护邻域关系；每个Agent至少绑定2个对等邻域节点；所有输出必须经过邻域校验才能向下游传递
2. **横向共识协议**：
   - 接口契约双向校验：前后端各自定义的接口自动做字段、类型、协议比对，不一致直接阻断提交
   - 模块交叉评审：相邻模块Agent互相检查接口兼容性、依赖合理性
   - 需求理解对齐：开发Agent输出的功能设计必须经上游需求Agent校验确认
3. **偏差同步机制**：任一Agent修改接口、调整逻辑时自动推送变更事件至所有关联邻域，邻域节点自动触发适配性检查
4. **局部自毁触发器**：输出与邻域共识偏差超阈值（如接口匹配度<80%）自动回滚提交；连续3次校验不通过主动上报稳态控制层

**标准交互协议**：
```
peerValidate(output: Code/Design, neighborIds: string[]): {
    passed: boolean,
    issues: Issue[]
}
```

### 2.3 分层稳态控制层（开发系统的「免疫系统+内分泌系统」）

**核心职能**：第三层兜底防线，独立于执行链路，全局巡检异常、修正系统性偏差。

**三级巡检体系（执行与巡检严格隔离）**：
1. **实时代码级巡检（免疫细胞）**：专属巡检Agent不参与编码，实时扫描所有提交代码——语法错误、代码规范、安全漏洞、复杂度、重复代码
2. **模块级阶段校验（形态稳态检查）**：预设里程碑节点（需求评审、架构设计、编码完成、测试通过），每节点暂停推进做全量结构化校验——需求覆盖度、架构合规性、接口完整性
3. **全局系统级调控（内分泌系统）**：定期全代码库整体扫描，识别系统性偏差（如多个模块同时跨层调用、都使用未批准依赖）

**强制组件**：代码质量巡检Agent（静态代码扫描）、架构合规巡检Agent（AST依赖分析）、安全漏洞巡检Agent（依赖漏洞/注入/敏感信息）、全局反馈调控器（系统性偏差→目标场梯度调整→全系统广播）

**标准纠偏流程**：
1. 个体异常 → 推送修复指令 → 对应Agent整改 → 复检通过
2. 系统性偏差 → 调整全局目标场权重 → 全系统Agent同步优化方向
3. 严重违规 → 阻断代码合入 → 触发回滚 → 重建执行链路

### 2.4 边界约束层（开发系统的「基因组+接触抑制」）

**核心职能**：在工具链底层做刚性约束，物理层面限定Agent能力边界。

> **关键原则**：所有约束硬编码在工具链层面，禁止仅通过自然语言Prompt做软约束。

**强制组件**：
1. **动作空间白名单**
   - 技术栈白名单：限定语言、框架、依赖包及版本，白名单外依赖无法从私有镜像源拉取
   - 工具权限白名单：限定可调用的IDE接口、数据库权限、系统命令
   - 输出格式白名单：强制代码结构、注释规范、接口格式，不符合格式无法提交
2. **发育路径约束**：标准研发流程状态机 `需求分析→架构设计→接口定义→编码实现→单元测试→代码评审→集成测试`，禁止跳阶段，未通过单元测试不得提交评审
3. **权限边界控制**：角色权限隔离（前端Agent不得修改后端代码）、读写权限分离（开发Agent无主分支合并权限）
4. **接触抑制规则**：单模块代码行数上限、单函数圈复杂度上限、单文件依赖数量上限、依赖深度限制、禁止循环依赖，避免"上帝类""上帝模块"无限膨胀

## 3. 标准开发运行闭环（全流程统一）

1. **目标场初始化**：需求+架构输入 → 编码器生成全局目标场 → 架构师确认 → 全系统广播
2. **分布式自组织开发**：各Agent获取自身目标梯度，并行开展工作，邻域实时交互校验
3. **邻域实时纠偏**：接口不匹配、需求理解偏差在邻域层自动修正，错误不向下游传递
4. **分层稳态巡检**：代码级实时扫描，阶段级全量校验，异常及时处置
5. **全局偏差修正**：发现系统性问题，调整目标场梯度，所有Agent统一优化方向
6. **终态对齐校验**：上线前全量做需求覆盖、架构合规、质量、安全四维校验，输出对齐度报告

## 4. 统一异常分级与响应机制

| 级别 | 偏离判定标准 | 对应生物现象 | 处置方式 |
|------|--------------|--------------|----------|
| 一级（轻度） | 代码风格不统一、命名不规范、小范围逻辑冗余 | 细胞轻微异常 | 邻域提示，自动修复，无需中断流程 |
| 二级（中度） | 接口不匹配、违反分层架构、单模块需求偏差 | 细胞脱离邻域调控 | 巡检器介入，回滚修改，限期整改，复检通过后方可继续 |
| 三级（重度） | 多模块架构违规、整体需求理解偏差、系统性质量问题 | 组织级发育异常 | 暂停开发，调整全局目标场，重新对齐需求/架构，全量整改 |
| 四级（癌变级） | 引入高危漏洞、越权操作、恶意代码、严重破坏架构 | 恶性肿瘤 | 强制终止Agent，清除对应代码，回滚版本，重建执行链路，人工介入 |

## 5. Agent角色与层级映射

| 角色 | 所属层级 | 核心职责 | 核心输出 |
|------|----------|----------|----------|
| 需求分析Agent | 目标场层 | 拆解需求、编码需求向量、维护需求版本 | 结构化需求文档、需求向量 |
| 架构设计Agent | 目标场层 | 技术方案设计、编码架构约束、维护架构版本 | 架构设计文档、架构约束向量 |
| 前端开发Agent | 自组织执行层 | 页面开发、接口对接、前端逻辑实现 | 前端代码、页面资源 |
| 后端开发Agent | 自组织执行层 | 业务逻辑、接口实现、数据库操作 | 后端代码、接口定义 |
| 测试用例Agent | 自组织执行层 | 用例设计、单元测试、集成测试 | 测试用例、测试报告 |
| 代码质量巡检Agent | 稳态控制层 | 代码规范、复杂度、重复代码扫描 | 质量扫描报告 |
| 架构合规巡检Agent | 稳态控制层 | 依赖关系、分层规则、接口规范检查 | 架构合规报告 |
| 安全漏洞巡检Agent | 稳态控制层 | 依赖漏洞、注入风险、敏感信息检测 | 安全扫描报告 |
| 平台管控引擎 | 边界约束层 | 执行所有硬边界规则、权限控制、流程管控 | 门禁校验结果、操作日志 |

## 6. 关键技术实现路径

| 能力 | 实现路径 |
|------|----------|
| 目标场量化 | 需求向量用Embedding相似度计算；架构合规用AST依赖分析；代码质量对接SonarQube等标准工具 |
| 邻域通信 | 基于事件总线实现点对点消息推送，变更事件实时触达关联节点 |
| 边界门禁 | Git Pre-commit钩子、CI流水线、私有镜像源权限控制实现硬约束拦截 |
| 梯度计算 | 静态分析结果 + 目标场权重，实时计算偏差值与优化方向 |
